## 1. Идея и общая схема

Пользователь прокручивает страницу. Прокрутка превращается в движение камеры по заранее заданной кривой в 3D-сцене:

```
комната на 7-м этаже  →  дверь  →  лестница подъезда  →  улица  →  прогулка мимо 12 вывесок  →  набережная  →  пляж  →  море и пирс
```

Страница обычная, вертикальная (высота `1900vh`), а 3D-холст приколот к экрану (`position: fixed`). Прокрутка меняет число `scrollState.target` от 0 до 1, камера плавно догоняет его и ставится в точку пути. Поверх холста лежит HTML-слой (карточки, точки-навигация, полоска прогресса).

Данные потока (однонаправленно):

```
window.scroll ──► scrollState.target ──► (сглаживание) scrollState.current
                                              │
                                   scrollToPath() — паузы у вывесок
                                              │
                                  PATH.getPointAt(u) — точка на кривой
                                              │
                      CameraRig: позиция + поворот головы + fov
                                              │
                       активная остановка → zustand store → Overlay (карточка)
```

Почему так, а не «сцены» с кнопками. Сначала была версия с тремя состояниями (комната, переход, город), переключаемыми по колесу. Она давала рывки и не работала на телефоне. Непрерывный путь по кривой проще: одно число (прогресс) описывает всё, его легко отлаживать (поставьте прогресс руками — и увидите кадр), и он работает с обычным скроллом, в том числе на тач-экранах.

## 2. Стек и запуск

| Что | Зачем |
| --- | --- |

| **GitHub Pages** | Хостинг, деплой воркфлоу при пуше в `main`. |

Запуск:

```bash
npm install
npm run dev            # http://localhost:4321
npm run build          # проверка сборки
BASE_URL=/3d-resume/ npm run build   # как на GitHub Pages (с подпапкой)
blender -b -P blender/make_assets.py # пересобрать модели
```

Требования: Node 20+, Blender 4.2+ (проверено на 5.2). Blender нужен только для моделей.

## 4. Система координат (важно!)

Эту тему нужно держать в голове, иначе вы будете путаться с «где перед, где право».

**three.js (в коде сцены):** `+Y` вверх, камера смотрит вдоль `-Z`. Улица идёт в сторону `-Z`. Левая сторона улицы — `x < 0`, правая — `x > 0`.

**Blender (в `make_assets.py`):** `+Z` вверх, `+Y` вперёд. Экспортёр glTF конвертирует: `(x, y, z)_blender → (x, z, -y)_three`.

Запомните соответствие: **Blender `+Y` = three `-Z`** (то есть «вперёд» для модели в Blender — это куда едет камера). Поэтому нос машины в Blender направлен в `+Y`, и в сцене она смотрит в `-Z`.

Для комнаты, где мы задаём мебель «как в three», удобно считать: `blender (x, y, z) = three (x, -z, y)`. Например, стол в three `(0, 0.75, -1.5)` в Blender — `(0, 1.5, 0.75)`.

Поворот объекта вокруг `Y` в three: положительный угол поворачивает «нос» (`-Z`) к `-X`, то есть **налево**. Это важно для поворота головы к вывескам на левой стороне (угол положительный).

## 5. Данные: остановки

Всё содержимое — в `src/data/resume.js`, массив `STOPS`:

```js
{
  id: "miet",                 // уникальный id (ключ React)
  side: "right",              // "left" | "right" — сторона улицы; null — комната
  kicker: "Сайт · 2025",      // маленькая метка над заголовком (и на вывеске)
  title: "МИЭТ",              // заголовок (и на вывеске)
  text: "Разделы и блоки…",   // описание в карточке
  stack: "Pug · SCSS · GSAP", // (необязательно) стек — на вывеске без картинки и в карточке
  href: "https://miet.ru",    // (необязательно) кнопка «Открыть ↗»
  links: [{label, href}],     // (необязательно) несколько кнопок (так сделаны «Контакты»)
  image: "/signs/miet.webp",  // (необязательно) скриншот на вывеске
  accent: "#ffb457",          // цвет рамки вывески и карточки

```

**Добавить остановку:** добавьте объект в массив `STOPS` (порядок = порядок вдоль улицы). Больше ничего править не надо: здание-герой, вывеска, пауза камеры, карточка и точка в навигации появятся сами. Улица удлиняется автоматически (`STREET_END` считается от числа остановок).

**Скриншот на вывеску:** положите `webp` (хватит 640 px по ширине, ~20–40 КБ) в `public/signs/` и укажите `image: "/signs/имя.webp"`. Без `image` на вывеске рисуется текст (заголовок и стек).

`resume.js` также экспортирует `SKILLS`, `PROJECTS`, `CONTACTS` — они собираются из `STOPS` и используются на странице `/resume/`.

## 6. Путь камеры и прокрутка

Файл: `src/utils/cameraPath.js`.

### Константы мира

```js
ROOM_FLOOR = 7        // высота пола комнаты над улицей (м)
ROAD_HALF  = 6        // полуширина проезжей части
EDGE       = 9        // |x| линии фасадов
STOP_SPACING = 22     // расстояние между вывесками вдоль улицы
FIRST_STOP_Z = -34    // z первой вывески
HERO_LEN   = 10       // длина «героя»-здания вдоль улицы
CROSS_Z    = -11      // z поперечной улицы у дома
STREET_END = LAST_HERO_Z - 40   // где кончается дорога
PROMENADE_END = STREET_END - 14 // набережная — 14 м
SAND_END   = PROMENADE_END - 22 // пляж — 22 м, дальше море
WALK_END_Z = SAND_END + 8       // где камера останавливается (песок у пирса)
```

Все размеры в метрах. Если хотите улицу длиннее — увеличьте `STOP_SPACING`. Шире — `ROAD_HALF` и `EDGE` (тогда проверьте текстуру дороги в `Street.jsx`, она нарисована в этих размерах).

### Кривая

`PATH` — `CatmullRomCurve3` через точки:

1. Комната: от `(0, 8.6, 2.5)` шаг к окну, затем дугой налево мимо стола к двери в левой стене `(-4, 8.63, -2.5)`.
2. Подъезд: четыре марша по 10 ступеней, между ними развороты на 180° на площадках (точки строятся циклом по константам `STAIRS`). На каждом марше три точки на одной прямой — чтобы сплайн не «провисал»; на площадке три точки дугой — это разворот. Дальше дверь подъезда `(-5, 1.65, -3.95)` и наискосок к середине дороги.
3. Улица: точки каждые 40 м с лёгким «петляющим» смещением `x = ±0.9` (чтобы шаг не был по линейке).
4. Конец: к началу пирса.

`PATH.arcLengthDivisions = 4000` — точность `getPointAt(u)` (равномерно по длине кривой, а не по параметру).

### Паузы у вывесок

Если просто привязать камеру к прокрутке, то мимо вывески камера пролетает, не давая её прочитать. Поэтому прокрутка → прогресс по пути идёт через функцию с «полками» (участками, где камера стоит), а между полками камера плавно разгоняется и тормозит:

- `STOP_GAP` — на каком расстоянии от вывески камера «встаёт» (9 м; на узком экране 17 м, чтобы вывеска помещалась по ширине).
- `PLATEAU = 0.012` — какая доля прокрутки отдана каждой паузе (на ней камера не двигается).
- `RAMP = 0.014` — какая доля прокрутки уходит на разгон после остановки и на торможение перед следующей. Без разгона скорость у вывески падала бы с полной до нуля за один кадр — это видно как рывок. Скорость на участке — трапеция (разгон, ровный ход, торможение), а положение камеры — её интеграл (`easeTrapezoid`).

Функции:

- `scrollToPath(s)` — прогресс прокрутки `s ∈ [0,1]` → прогресс пути `u ∈ [0,1]`.
- `stopScroll(i)` — какой `s` соответствует остановке `i` (используется точками-навигацией, чтобы по клику прокрутить к нужной вывеске).

Хотите дольше стоять у вывесок — увеличьте `PLATEAU` (не больше ~0.03 при 12 остановках).

### Высота прокрутки

В `ResumeCanvas.jsx`: `const SCROLL_HEIGHT = "1900vh"`. Чем больше, тем медленнее «идёте» на один жест. Подбирайте на телефоне.

### scrollState

`src/store/useSceneStore.js`:

```js
export const scrollState = { target: 0, current: 0 };
```

`initScroll()` слушает `scroll` и `resize` и пишет `target = scrollY / (scrollHeight − innerHeight)`. `current` — это уже сглаженное значение, его двигает `CameraRig`.

## 7. Камера: сглаживание, повороты, свободный обзор

Файл: `src/scenes/CameraRig.jsx`. Всё в одном `useFrame`.

### Сглаживание

```js
current += (target − current) * (1 − exp(−dt * 5));
```

Экспоненциальное сглаживание независимо от FPS. `dt` ограничен 0.05 с, чтобы после паузы вкладки камера не «прыгала».

### Позиция и наклон по касательной

`fwd` — единичный вектор вдоль кривой (разность двух соседних точек). От него берём:
- `yaw` (поворот вокруг Y) — `atan2(−fwd.x, −fwd.z)`;
- `pitch` (наклон) — `asin(fwd.y)`: именно он наклоняет взгляд вниз на лестнице (с запасом ×1.25, чтобы в кадре были ступени, а не стена напротив).

Покачивание при ходьбе: `bob = sin(u * PATH_LENGTH * 1.9) * 0.03 * walking`, где `walking` плавно включается, когда камера уже внизу.

### Поворот головы к вывескам

Для каждой остановки с `side`:

```js
dz    = camera.z − signZ                         // сколько метров до вывески (+ = впереди)
angle = atan2(−(signX − camera.x), max(dz, 6))   // угол на вывеску
w     = sstep(STOP_GAP+23, STOP_GAP+9, dz) * sstep(STOP_GAP−15, STOP_GAP−5, dz)
yaw  += angle * w
```

`w` — вес «смотреть на вывеску»: плавно растёт за ~23 м до остановки, держится и плавно спадает после неё. **`max(dz, 6)` важен**: при `dz → 0` угол стремится к 90° и меняется скачком — это давало рывок при повороте. Нижняя граница убирает сингулярность. `sstep` — smoothstep, умеющий работать с «перевёрнутыми» границами.

Питч-добавка смотрит чуть вверх на вывеску (`4.6` — высота центра вывески):
`pitch += atan2(4.6 − camera.y, dist) * 0.8 * w`.

Сглаживание поворота: `yaw += (target − yaw) * (1 − exp(−dt * 3))`. Меньше число — медленнее, плавнее.

### Активная остановка

Активной считается ближайшая вывеска, до которой ещё `dz ≥ STOP_GAP − 6`. Пока камера в комнате — активна остановка 0 (интро); после последней — остаётся последняя. Когда активная меняется, пишем в store: `setActiveStop(i)`.

### Свободный обзор

Можно тянуть мышью или пальцем по сцене — голова поворачивается:

- слушатели `pointerdown/move/up` на `window`, реагируют только если цель — `<canvas>`;
- `L.ty`/`L.tp` — целевые углы (из движения), `L.yaw`/`L.pitch` — сглаженные;
- через 1.2 с после отпускания цель плавно возвращается к нулю (`exp(−dt*2.5)`);
- в CSS у канваса `touch-action: pan-y`: вертикальный жест остаётся прокруткой, горизонтальный вращает вид.

Итоговый поворот: `rotation.set(pitch + L.pitch, yaw + L.yaw, 0, "YXZ")` — порядок `YXZ` обязателен для «головы» (сначала поворот по горизонтали, потом наклон).

### У моря

Когда камера приближается к пляжу (`sea` от 0 до 1): `fov` растёт с 55° до 70°, взгляд слегка вниз — чтобы в кадр помещались и луна наверху, и её блик на воде.

## 8. Небо, звёзды, луна

Файл: `src/scenes/Sky.jsx`. Вся группа каждый кадр копирует позицию камеры — небо «в бесконечности», сколько ни иди.

- **Купол**: сфера радиусом 450 с `BackSide` и своим шейдером: градиент от светящегося горизонта (`vec3(0.115,0.125,0.26)`) через средний (`0.03,0.05,0.13`) к почти чёрному зениту. Не пишет в буфер глубины (`depthWrite: false`), рисуется первым (`renderOrder -3`).
- **Звёзды**: `Points` на верхней полусфере радиуса 400, размер и мерцание из случайного атрибута `aRandom`. Количество — проп `stars` (1800 на десктопе, 900 на мобильном — см. `ResumeCanvas.jsx`).
- **Луна**: сфера с процедурной текстурой (пятна «морей» на canvas) + спрайт-ореол с аддитивным смешиванием.
- **`MOON_DIR`** — направление на луну: `(-0.18, 0.5, -1)` нормированное (≈ 26° над горизонтом). Экспортируется и используется:
  - направленным светом (`directionalLight`) — свет луны на дороге и стенах;
  - шейдером зданий и стеклянных башен — освещение граней и блик;
  - шейдером моря — блик (дорожка) на воде.

Хотите луну выше/ниже или в другую сторону — меняйте только `MOON_DIR`, всё остальное подтянется. Но проверьте, что она остаётся в кадре (вертикальный `fov` 55°, питч +0.12 на улице).

## 9. Город: здания и шейдер фасадов

Файл: `src/scenes/Street.jsx`.

### Расстановка зданий

Функция `buildBuildings()` возвращает массив `{x, z, w, h, d}`. Детерминированный генератор `rng(7)` — город одинаковый при каждой загрузке.

Ряды вдоль каждой стороны улицы:

1. **Первый ряд** — вплотную к линии фасадов `EDGE`. Длина здания вдоль улицы 7–14 м, ширина 9–17, высота 9–35. Там, где стоит «герой» (вывеска), генерируемое здание пропускается.
2. **Второй ряд** — на `EDGE + 20`, выше (26–66 м).
3. **Дальний силуэт** — на `EDGE + 48`, ещё выше (40–100 м) — это горизонт города.
4. **Герои** — по одному на остановку, ширина 13, высота 24 + (i % 3) × 5.
5. **Дом с комнатой** — длинный низкий корпус `160 × 20 × (ROOM_FLOOR − 0.06)` на торце улицы (комната стоит у него «на крыше»; зазор 0.06 м убирает мерцание плоскостей).

Все здания — один `InstancedMesh` с одним кубом (`BoxGeometry 1×1×1`), у каждого экземпляра масштаб = размеры здания. **Это одна отрисовка на весь город.**

### Крыши и изгородь

Для зданий выше 14 м добавляются на крышу (отдельные `InstancedMesh`): техэтаж (`penthouse`), три блока кондиционеров, два бака для воды (цилиндры). Вдоль первого ряда — живая изгородь (зелёные низкие боксы). Размеры и позиции — в `Buildings()`.

### Шейдер фасадов

Здания рисует самописный `ShaderMaterial` (`buildingMaterial`). Фасад — **процедурный**, без текстур: по мировым координатам стены считается сетка этажей и окон.

Вершинный шейдер передаёт во фрагментный:
- `vWorld` — мировую позицию;
- `vNormal` — нормаль (стены `±x/±z` отличаем от крыши);
- `vSeed` — случайное число экземпляра (из его позиции) — оно выбирает цвет, тип фасада, наличие балконов;
- `vCenter`, `vScale` — центр и размеры экземпляра (из `instanceMatrix`), чтобы знать «где мы на фасаде» (`uLocal` от −0.5 до 0.5).

Фрагментный шейдер:

1. **Палитра** (по `vSeed`): белый, песочный, серо-голубой, светло-серый.
2. **Освещение**: `base * (0.15 + 0.5*moonLight + 0.1*max(n.y,0))`, холодный оттенок `(0.8, 0.88, 1.12)`, верх чуть светлее.
3. **Два типа фасада** (по `fract(vSeed * 13.7)`):
   - **Панельный** (как на первом референсе): сетка окон 3×3 м, окно занимает ~42×50 % ячейки, 34 % окон «горят» тёплым или холодным светом, рамка вокруг окна. У части домов (`vSeed > 0.42`, ширина фасада > 6 м) — вертикальная **полоса балконов**: на каждом этаже светлая плита-перекрытие, ограждение из вертикальных балясин, тёмная ниша за ним с редкой подсветкой.
   - **Стеклянная башня** (второй референс): ячейка 1.7×3 м, тонкие металлические импосты, горизонтальный пояс на этаже, коричневые панели вместо части стёкол, металлическая рамка по углам здания. Стекло **отражает небо**: `reflect(V, n)` даёт цвет от горизонта до зенита, плюс блик луны (`pow(dot(R, MOON_DIR), 90)`), плюс слабые «городские» огни у земли.
4. **Первый этаж** (`y < 3 м`): тёмный цоколь с редкими тёплыми витринами.
5. **Туман**: `1 − exp(−(density * depth)²)` — тот же закон, что у `fogExp2` в three.js, чтобы здания и остальные объекты тонули согласованно.

Чтобы **изменить внешний вид**, правьте строки шейдера:
- доля освещённых окон — `step(0.66, r)` (больше число = меньше окон светится);
- размер ячейки — `vec2 cell = vec2(3.0, 3.0)`;
- цвета палитры — векторы `base`;
- вероятность стеклянных башен — `step(0.55, fract(vSeed * 13.7))`.

Ловушка при правке GLSL: ошибка компиляции шейдера **не роняет приложение**, а молча делает объект невидимым; смотрите консоль браузера (`THREE.WebGLProgram: Shader Error`).

## 10. Дорога, перекрёсток, набережная, море

Всё в `Street.jsx`.

- **Дорога**: плоскость 40 × (длина) с текстурой, нарисованной на `canvas` 512×512 (40 м на тайл): земля, асфальт, тротуары с плиткой, бордюры, пунктир по центру (период 8 м), сплошные краевые, шум. Повторяется по Z.
- **Перекрёсток**: поперечная улица — отдельная плоскость 160 × 12 на высоте 0.004 (чуть выше основной), с `polygonOffset`, чтобы не мерцала. Машины сворачивают на неё (см. раздел 12).
- **Набережная** — плоскость 160 × 14 из шумной «каменной» текстуры.
- **Пляж** — плоскость 160 × 22, песочный шум, на 4 см ниже набережной.
- **Пирс** — бокс 3.4 × 0.22 × 74 м и столбики-сваи через 6 м.
- **Море** — отдельный `ShaderMaterial` на большой плоскости (1400 × 900) на высоте −0.5 м:
  - нормали из суммы синусов (волны), анимируются временем `uTime`;
  - блик луны: `pow(dot(reflect(V, n), MOON_DIR), 260)` (узкий блеск) + `pow(…, 40)` (широкое сияние);
  - френель: у горизонта вода отражает небо (светлее), вблизи — тёмная;
  - пена у берега: полоса вдоль `uShore` с бегущей модуляцией;
  - туман — как у зданий.

**Туман**: `FOG_COLOR = "#141a3a"`, `FOG_DENSITY = 0.0105`. Цвет совпадает с цветом горизонта неба, иначе будет видна «граница». Для самописных шейдеров туман считается вручную (`uFog`, `uFogDensity`).

## 11. Фонари и вывески

### Фонари

`Lamps()`: столбы каждые 16 м, чередуя стороны, на `x = ±(ROAD_HALF + 0.5)`; столб не ставится в 5 м от вывески на своей стороне (иначе перекрывает её). Три `InstancedMesh`/`Points`:
- столбы — цилиндры;
- светлые пятна на асфальте — аддитивные плоскости с радиальным градиентом (дешёвая «имитация света», настоящих источников нет);
- светящиеся лампы — `Points` с текстурой-свечением.

Реального освещения от фонарей нет — это сознательный выбор: десятки `PointLight` убили бы мобильные.

### Вывески

`Signs()`: для каждой остановки со `side` — плоскость на фасаде героя (высота центра 4.6 м) с текстурой, нарисованной на `canvas` 768×384 в «дизайн-координатах» 1024×512 (`ctx.setTransform(0.75, …)`).

- Сначала рисуется **текстовая** вывеска (метка, заголовок, стек), потом, когда загрузится картинка (`new Image()`), перерисовывается со скриншотом и градиентом под подпись, `texture.needsUpdate = true`.
- Заголовок автоматически уменьшается, пока не поместится в 1–2 строки.
- Позади — второй плоскость той же формы чуть больше с аддитивным цветом акцента — мягкое свечение вокруг.
- Поворот: левая сторона `rotation.y = +π/2`, правая — `−π/2` (чтобы нормаль смотрела на дорогу).

## 12. Модели из Blender и их расстановка

Файл: `src/scenes/Props.jsx`.

### Загрузка и инстансинг

`useGLTF(asset("/models/props.glb"))` отдаёт сцену. Каждая модель в ней — узел с именем (`tree`, `tree_b`, `bench`, `bin`, `car_a` … `car_e`). Для узла собираем все `Mesh` (геометрия + материал) и создаём `InstancedMesh` на каждый материал. Итог: **сотни деревьев/машин — десяток отрисовок.**

Функция `partsOf(scene, name)` ищет узел по имени среди детей сцены и обходит его потомков.

### Раскладка (`buildLayout`)

| Объект | Правило |
| --- | --- |
| Деревья (`tree`, `tree_b` 50/50) | по обе стороны, шаг 22 м (стороны сдвинуты друг от друга), `x = ±(ROAD_HALF + 1.9)`; не ставятся в 10 м от вывески на своей стороне |
| Скамейки + урны | каждые 44 м, чередуя стороны, лицом к дороге; тоже не перед вывесками |
| Припаркованные машины | вдоль бордюров, шаг 8–14 м, 45 % мест занято; не на перекрёстке |
| Едущие машины | 12 штук, 5 типов по кругу |

### Типы машин

`car_a` — фастбэк (по Audi A7), `car_b` — суперкар с антикрылом (по Ferrari F40), `car_c` — внедорожник, `car_d` — полицейский внедорожник, `car_e` — зелёный фургон.

### Движение (конечный автомат)

Полосы: `x = ±2.4`; поперечная улица: `z = CROSS_Z ± 2.5`. Машины двух видов:

- **`in`** (полоса `x = −2.4`, едет к дому): `lane` → дошла до `CROSS_Z + 2.5` → `cross` (поворот на `−x`, едет по поперечной улице) → дошла до `x = −80` → «респавн» на дальнем конце улицы.
- **`out`** (полоса `x = +2.4`, едет от дома): приезжает по поперечной улице (с `x = −80`) → доезжает до `x = 2.4` → поворачивает на `−z` → едет к концу улицы → респавн на поперечной.

Поворот делает функция `turnTo`: плавное приближение угла к целевому с кратчайшим обходом (`atan2(sin, cos)`). Так машины **никогда не заезжают в здания** (в первой версии они ездили сквозь дом — это была ошибка с границами).

Каждый кадр пересчитываются матрицы только у едущих машин (`animated` для `car_*`).

### Мигалки полиции

Материалы `police_blue` и `police_red` (общие для всех полицейских экземпляров) в `useFrame` по очереди получают то яркий, то слабый `emissiveIntensity` — 5 раз в секунду.

## 13. Скрипт Blender подробно

Файл: `blender/make_assets.py`. Запуск: `blender -b -P blender/make_assets.py` (`-b` — без окна). Пишет `public/models/props.glb` и `room.glb`.

### Идея

Модели строятся **кодом**: из примитивов (`primitive_cube_add`, `cylinder`, `ico_sphere`, `cone`, `torus`), из профилей (`extrude_poly`) и из `bmesh`. Это даёт воспроизводимость (меняете число → пересобираете) и удобные правки без ручного моделирования. Все объекты сцены каждой модели склеиваются (`join`) в **один меш с несколькими материалами**, чтобы в three.js получить минимум узлов.

### Хелперы

| Функция | Что делает |
| --- | --- |
| `mat(name, color, rough, emit, strength, metal)` | материал Principled BSDF с кэшем; цвет в hex (sRGB → линейный) |
| `box(size, loc, m, rot, bevel)` | куб с размерами `size` (метры), опционально со скруглением |
| `cyl(r, depth, loc, m, rot, verts)` | цилиндр |
| `ico(r, loc, m, sub, squash)` | икосфера |
| `cone(...)` | усечённый конус |
| `branch(p0, p1, r0, r1, m)` | «ветка» — конус между двумя точками (стволы, трубки, стойки) |
| `lumpy(r, loc, m, …)` | икосфера с шумом вершин — «комок листвы» |
| `extrude_poly(pts, width, m, name, bevel)` | профиль в плоскости (y, z), выдавленный по x — основа кузова машины |
| `leaf`, `flower`, `leafy_plant` | листья/цветы/комнатные растения |
| `join(objs, name)` | склеить в один объект, origin в (0,0,0) |
| `export(path, objs)` | экспорт выбранных объектов в `.glb` |

### Правила, чтобы экспорт не ломался

1. **Применяйте трансформации** (`finish()` делает `transform_apply` для rotation и scale) — иначе масштаб/поворот окажутся в узле, а не в вершинах, и инстансинг в three.js покажет не то.
2. **Имя объекта = имя узла в glTF.** `join(parts, "car_a")` → `scene.children.find(c => c.name === "car_a")` в `Props.jsx`.
3. **Нос машины — в `+Y` Blender** (= `−Z` three), низ — на `z = 0`, центр по `x`.
4. **Эмиссия** (`mat(..., emit, strength)`) — для фар, ламп, экранов. Выше ~4 в three.js выжигается в белое: для цветных огней (RGB-кольца) брали 1.6–1.8.
5. **Металличность без окружения даёт чёрный цвет!** В сцене нет карты окружения, поэтому металлы выглядят чёрными. У кузовов `metal=0.1`, у дисков и хрома `0.3`. Если нужен металлический блеск — добавьте `scene.environment` в three.js или оставьте низкую металличность.
6. **Сглаживание**: `smooth(o)` вызывает `shade_smooth_by_angle(38°)` — машины получают гладкие кузова без «граней».
7. **Вершинные цвета (шторы)**: у штор материал с узлом `Color Attribute` (`ShaderNodeVertexColor`, слой `Col`) подключён к `Base Color`; цвет складок и узор записаны в атрибут `FLOAT_COLOR`. Экспортёр кладёт его в `COLOR_0`, three.js подхватывает автоматически.
8. **Двусторонний материал** (`use_backface_culling = False`) — для штор (плоский лист без толщины).

### Как устроена машина

`car(name, color, style, extras)`:

1. Берётся описание стиля из `CAR_STYLES`: профиль кузова `lower` (список `(y, z)`), профиль стёкол `glass`, ширина `w`, радиус колеса `r`, клиренс `clear`, флаг `wing`, (для фургона — `cargo`).
2. Кузов — `extrude_poly(lower, w, …)` со скруглением; стёкла — выдавленный профиль **уже кузова** (`w − 0.26`), поэтому выглядят вдавленными; поверх — тонкая крышка крыши цвета кузова.
3. Колёса (`wheel`): шина, диск, тормозной диск и 5 спиц (поворот `box` вокруг оси x с шагом 36°).
4. Бамперы, решётка, фары (эмиссия), задние огни, номера, выхлопные трубы, зеркала, антенна.
5. `extras(st, w, front, rear, c)` — функция, возвращающая **дополнительные части** (спойлер, мигалки полиции, кенгурятник, круглые фары фургона).

**Добавить новый тип машины:**

```python
CAR_STYLES["pickup"] = dict(
    lower=[(2.3, 0.4), (2.3, 0.9), (1.9, 1.05), (0.6, 1.1), (-2.4, 1.0), (-2.4, 0.4)],
    glass=[(0.6, 1.1), (0.1, 1.65), (-0.5, 1.65), (-0.6, 1.1)],
    w=1.95, r=0.39, clear=0.1, wing=False)

# в build_props():
car("car_f", "#aa7a2a", "pickup")
```

После этого в `Props.jsx` добавьте `"car_f"` в `CAR_TYPES` и ключ `car_f: []` в `items` внутри `buildLayout`, пересоберите модели.

## 14. Комната

Файл: `src/scenes/IntroScene.jsx`.

### Каркас

Стены, пол, потолок — простые плоскости (комната 8×8×4 м). Задняя стена собрана из четырёх сегментов вокруг проёма окна (`WIN_HALF_W = 1.6`, низ 0.9, верх 3.4). Текстуры пола (паркет) и стен (штукатурка) рисуются на `canvas` кодом — загрузка картинок через `TextureLoader` давала артефакты в некоторых окружениях.

Вся комната завёрнута в `<group position={[0, ROOM_FLOOR + 0.03, 0]}>` — поднята на этаж. Поднимать только группу, а не пересчитывать координаты внутри.

### Мебель

Мебель — из `room.glb` (`RoomProps`). Внутри: рабочий стол с ноутбуком, стул, лампа, ковёр, два книжных шкафа, люстра, окно с карнизом и шторами, цветы на подоконнике, большое растение, картины и часы, телевизор с тумбой и вазами, второй стол с ПК и креслом.

Все расстановки заданы в `build_room()` в `make_assets.py` в координатах Blender (см. раздел 4).

### Экраны с «обоями»

Экраны (ноутбук, ТВ, монитор ПК) в Blender — **отдельные объекты-плоскости с UV** (`laptop_screen`, `tv_screen`, `pc_screen`), не склеенные с остальным. В `RoomProps` они находятся по имени и получают `MeshBasicMaterial` с `CanvasTexture`, нарисованной кодом:

- `drawLaptop` — синие обои с лучами и «окном редактора кода»;
- `drawTV` — пейзаж: горы над озером с отражением;
- `drawPC` — цветной градиент.

`texture.flipY = false` обязателен: UV в glTF уже перевёрнуты.

Хотите другие обои — правьте функции `drawLaptop/drawTV/drawPC` (обычный Canvas 2D) или подставьте картинку через `TextureLoader`.

### Пластиковое окно (`src/scenes/PlasticWindow.jsx`)

В проёме стоит обычное трёхсекционное ПВХ-окно: рама по периметру, два импоста (стойки между секциями), боковые секции глухие, средняя — створка на петлях с ручкой. Размеры — от профиля 70 мм: рама ~70 мм, створка ~75 мм, импост ~80 мм, штапик (планка, прижимающая стекло) ~20 мм. Подоконник — в `make_assets.py` (белый ПВХ).

Что здесь стоит разобрать:

- **Почему окно в коде, а не в Blender.** Мебель комнаты склеена в одну модель, двигать её часть нельзя. А створка должна открываться — ей нужен свой объект (`<group ref={sash}>`).
- **Ось вращения — это начало координат группы.** Геометрия створки построена «от петли»: `x = 0` — ось петель, створка тянется вправо. Группа стоит в точке петли, и `rotation.y` поворачивает створку как настоящую. Если бы геометрия была построена от центра створки, она крутилась бы вокруг своей середины, как вертушка.
- **Сейчас окно закрыто** (выходим через дверь), но створка осталась отдельной группой: задайте `sash.current.rotation.y = -1.2` — распахнётся. Тот же приём открывает двери подъезда, см. ниже.
- **Склейка геометрий (`mergeGeometries`).** Каждый `<mesh>` — отдельный вызов отрисовки (draw call). Окно из 45 брусков — 45 вызовов. Все неподвижные белые бруски склеены в одну геометрию и рисуются одним вызовом; на всё окно выходит 8 вызовов.
- **Стекло без отражений.** Настоящие отражения дороги. Здесь стекло — прозрачная плоскость с текстурой, на которой нарисованы два косых блика (`glassTexture`). `depthWrite: false` нужен, чтобы стекло не закрывало прозрачные объекты за окном (звёзды, свечение фонарей).

### Подъезд (`src/scenes/Stairwell.jsx`)

Из комнаты выходим в дверь на лестничную клетку и спускаемся пешком: 4 марша по 10 ступеней, развороты на площадках, внизу почтовые ящики и стальная дверь на улицу. Все размеры лежат в `STAIRS` (`utils/cameraPath.js`): по одним и тем же числам строятся и ступени, и путь камеры — поэтому камера идёт ровно по маршам.

- **Один материал на сотни деталей — цвет в вершинах.** Ступени, площадки, перила, соседские двери, ящики — около 400 брусков разного цвета. Цвет записан не в материал, а в атрибут `color` каждой вершины (`box()` в файле), материал один (`vertexColors: true`), всё склеено в одну геометрию — один вызов отрисовки.
- **UV от мировых координат.** Стены режутся на куски вокруг дверных проёмов. Если бы у каждого куска UV шли от 0 до 1, рисунок на кусках не совпадал бы. Поэтому `wall()` считает UV из положения вершины в мире.
- **Краска идёт наискосок вдоль лестницы** (`floorShift`): граница «зелёная краска / побелка» опускается вместе с маршем, как в настоящем подъезде. Для этого стена разрезана по границам маршей, а на каждом куске сдвиг меняется линейно.
- **Двери открываются от расстояния до камеры** (`SwingDoor`): угол = `smoothstep(3 м → 1.3 м)`. Не от времени — поэтому при прокрутке назад дверь сама закрывается и открывается в обратном порядке, отдельного кода не нужно. Группа двери стоит в точке петли, полотно тянется по локальной оси X — поворот группы и есть открывание.
- **Одна лампа вместо трёх.** Каждый источник света считается для каждого пикселя всех освещаемых объектов сцены. Поэтому лампа одна и едет по высоте за камерой; на улице её яркость 0. Именно яркость, а не `visible = false`: three.js компилирует шейдеры под число источников, и выключение лампы заставило бы пересобрать их — заметная заминка прямо на выходе.
- **Шахта в корпусе дома.** Дом — коробка в общем `InstancedMesh` зданий. Чтобы её крыша и фасад не закрывали лестницу, корпус собран из трёх коробок с прорезью под шахту (`buildBuildings` в `Street.jsx`), а наружные стенки шахты добавлены отдельно.
- **Угол без скачка через π.** `atan2` отдаёт угол от −π до π; на разворотах он перепрыгивает с +π на −π, и сглаживание пошло бы «длинной дорогой», через полный оборот. В `CameraRig` целевой угол сдвигается на целое число оборотов — к ближайшему от текущего.
- **В доме прокрутка «медленнее».** Весь путь по дому (до `U_EXIT`) растянут на первые 20 % прокрутки (`INDOOR`), иначе разворот на площадке проскакивал бы за один щелчок колеса.

### Свет в комнате

Несколько `pointLight` с ограниченной дальностью (`distance`), чтобы свет комнаты не «протекал» на улицу: люстра, настольная лампа, подсветка от окна, голубое свечение ноутбука и ТВ, фиолетовое от RGB-блока.

Физически корректные единицы (three r155+): значения `intensity` для `pointLight` на порядок больше «киношных». Если сцена выглядит чёрной, увеличивайте интенсивность в 5–10 раз, а не «чуть-чуть».

### 15б. Прелоадер с прожиганием

Файлы: `src/components/Preloader.jsx`, `ReadySignal` в `ResumeCanvas.jsx`, статический `.boot` в `pages/index.astro`, стили `.boot` в `layouts/Layout.astro` и `.preloader__fire` в `journey.css`.

**Зачем.** Первая загрузка тяжёлая: модели, компиляция шейдеров. Без прелоадера пользователь видит чёрный экран до 25 секунд (на слабом GPU). Прелоадер показывает прогресс, а потом красиво «сжигает» себя, открывая живую сцену. Идея — из конструктора анимаций (раздел «Прожигание» в `konstruktor-3d`), здесь реализована на чистом WebGL-шейдере.

**Три слоя, чтобы не было пустого экрана:**

1. **Статический `.boot` в HTML** (`index.astro`) — виден сразу, ещё до загрузки JS: монограмма «ДР» и крутящееся кольцо. Его стили лежат в `Layout.astro`, потому что CSS из `journey.css` приходит только вместе с JS.
2. **React-`Preloader`** при монтировании удаляет статический `.boot` и рисует **тот же вид** с реальными процентами и кольцом прогресса, так что подмены не видно.
3. **Огненный канвас** `.preloader__fire` — отдельный WebGL-контекст поверх сцены, создаётся только в момент поджога и уничтожается (`WEBGL_lose_context`) после.

**Откуда берётся «готово».**

- Прогресс — `useProgress()` из drei: он считает загрузки через `THREE.DefaultLoadingManager` (модели `.glb`). Показываем не больше 88 %, пока сцена не готова.
- Готовность — компонент `ReadySignal` внутри `<Suspense>`: он монтируется, только когда Suspense дождался всех моделей, и ждёт ещё 4 кадра `useFrame` (за них компилируются шейдеры), после чего пишет `ready = true` в store.
- Когда `ready` и число на экране дошло до 97 %, ждём минимум `MIN_SHOW_MS = 1400`, чтобы прелоадер не мигал на быстром соединении, и запускаем прожигание.

**Шейдер прожигания** (фрагментный, на весь экран):

```glsl
v = length(p) * 0.95 + (coarse - 0.5) * 0.6 + (fine - 0.5) * 0.14;  // «очередь прогорания»
t = mix(-0.4, 1.5, progress);                                         // фронт огня
f = v - t;     // f < 0 → уже сгорело: прозрачно, видна сцена
```

- `v` — «когда эта точка сгорит»: ближе к центру горит раньше, плюс крупный и мелкий шум делают фронт рваным (это та же идея, что в конструкторе: поле очерёдности + порог).
- Полоса `0 < f < 0.028` — раскалённая кромка (от жёлто-белого к оранжевому, мерцает).
- Дальше — тлеющая обугленная кромка, которая плавно переходит в цвет фона; поверх случайные искры.
- Прогресс `progress` идёт от 0 до 1 за `BURN_MS = 2600` мс с `ease-in-out`.

**Настройка внешнего вида.** Откройте `http://localhost:4321/?burn=12000` — прожигание растянется на 12 секунд, и вы сможете рассмотреть огонь. Что можно крутить:

| Хочу | Что менять в `FRAG` |
| --- | --- |
| Огонь начинается не из центра | `length(p)` → `length(p - vec2(0.3, 0.1))` |
| Более рваный фронт | множитель `0.6` у `coarse` |
| Толще раскалённая кромка | порог `0.028` (в двух местах) |
| Другой цвет огня | векторы `hot` и `ember` |
| Больше искр | порог `0.992` у `spark` (меньше число — больше искр) |

**Мелочи, которые важны:**

- пока идёт загрузка, прокрутка заблокирована (`overflow: hidden` на `<html>`) и страница возвращается наверх (`history.scrollRestoration = "manual"`), иначе браузер мог бы восстановить позицию из прошлого визита и «пропустить» комнату;
- при `prefers-reduced-motion` огня нет — просто плавное исчезновение за 450 мс;
- разрешение огненного канваса ограничено (`dpr ≤ 1.25`): это размытое пламя, ему не нужна чёткость.

### 15в. Рыбалка в конце пути

В самом конце прокрутки появляется кнопка «Порыбачить с пирса». Камера уходит на конец пирса, в руках удочка. Управление — одна кнопка (мышь, палец или пробел): зажали — замах, отпустили — заброс; поплавок нырнул — нажать (подсечка); дальше держать, чтобы мотать, и отпускать, когда рыба рвётся, иначе лопнет леска. Каждая рыба — навык из резюме; всего их 8.

Игра разложена на три файла, и это главное, что стоит разобрать:

| Файл | За что отвечает | Чего в нём нет |
|---|---|---|
| `src/game/fishing.js` | правила: состояние и функция `step(g, dt, pressed)` | ни three.js, ни React |
| `src/scenes/FishingRig.jsx` | 3D: удочка, леска, поплавок, круги, рыба; каждый кадр зовёт `step` | правил игры |
| `src/components/FishingHud.jsx` | кнопки, подсказка, шкалы, карточка улова | 3D и правил |

- **Конечный автомат.** Игра всегда ровно в одной фазе: `idle → charging → flying → waiting → bite → reeling → caught` (или `lost`). В `step` — один `switch` по фазе; схема нарисована в начале `fishing.js`. Так нельзя попасть в невозможное состояние вроде «мотаем, но ещё не забросили».
- **«Нажали» — это фронт, а не уровень.** `justPressed = pressed && !wasPressed`. Плюс флажок `tap`: быстрый тап может начаться и закончиться между двумя кадрами — флажок запоминает, что нажатие было.
- **Покадровое — мимо React.** Сила замаха и натяжение меняются 60 раз в секунду. Они лежат в обычном объекте (`game/fishingRuntime.js`), а шкалы обновляются прямой записью в `style` через `ref`. В хранилище zustand уходит только смена фазы — React перерисовывает интерфейс несколько раз за партию, а не каждый кадр.
- **Удочка «в руках».** Группа каждый кадр копирует положение и поворот камеры, удочка — её ребёнок со сдвигом вправо-вниз. `FishingRig` стоит в дереве после `CameraRig`, поэтому берёт уже посчитанную в этом кадре камеру.
- **Леска — кривая Безье** из 16 точек от кончика удочки к поплавку; средняя точка опущена — это провис. Геометрия создаётся один раз, каждый кадр переписываются только числа в том же массиве (`needsUpdate = true`).
- **Камера-оператор.** `fishCam` говорит `CameraRig`, куда смотреть и какой угол обзора: пока ждём поклёвку — сильное приближение на поплавок (34°), при вываживании — шире. Переход с прогулки на пирс — `blend` от 0 до 1 за 4.5 с.
- **Нечестный поплавок.** На 17 метрах поплавок честного размера — два пикселя. Он растёт с расстоянием: игроку важно видеть поклёвку, а не масштаб.

Хотите поменять сложность — числа в `step`, ветка `reeling`: скорость выбора лески, рост натяжения в рывке, длина рывков. Рыб — в массиве `FISH`.

## 16. Производительность и мобильные устройства

Что уже сделано:

- **Инстансинг**: город — 1 вызов, крыши/кондиционеры/баки/изгородь — по 1, деревья/машины — по числу материалов модели.
- **Шейдерные фасады** вместо текстур: нет памяти под текстуры, бесконечные вариации.
- **Лёгкие огни**: пятна света, свечение лампы — спрайты и аддитивные плоскости, а не `PointLight`.
- **Ограничение разрешения**: `dpr={[1, 1.5]}` на мобильных (`< 768 px`), `[1, 2]` на десктопе; сглаживание выключено на мобильных; звёзд 900 вместо 1800.
- **Туман** прячет границы мира: `far = 700`, но дальше ~250 м видно только дымку.
- **Модели лёгкие**: `props.glb` ~0.8 МБ, `room.glb` ~1.3 МБ. Если нужно легче: уменьшите число клавиш ноутбука, число сегментов штор (`nx, nz` в `curtain_panel`), подразбиение листьев.
- **Скриншоты вывесок** по 640 px.
- **`near: 0.25`** вместо 0.1 — меньше мерцания плоскостей на расстоянии.

Что смотреть, если на телефоне тормозит:

1. Откройте DevTools → Performance, посмотрите, где время: чаще всего **fragment-шейдер зданий** (на экране много пикселей, а шейдер длинный).
2. Снизьте `dpr` (например `[1, 1.25]`) — самый быстрый рычаг.
3. Уберите стеклянные башни: в шейдере `step(0.55, …)` → `step(2.0, …)`.
4. Уменьшите число едущих машин (цикл `i < 12`) и `stars`.

### Как измерить, а не гадать

В режиме разработки рендерер доступен из консоли: `window.__gl.info.render` показывает `calls` (вызовы отрисовки за кадр) и `triangles`. Сейчас: в комнате ~200 вызовов и ~165 тыс. треугольников, на улице ~110–135 вызовов и ~156 тыс. На MacBook с M4 Pro вся прокрутка идёт ровно 120 кадров/с, ни одного кадра длиннее 20 мс — узкого места на такой машине нет, поэтому «оптимизировать вслепую» нечего.

### Автоматическая плотность пикселей (`AdaptiveDpr` в `ResumeCanvas.jsx`)

Чужой ноутбук может быть слабее. Самый дешёвый рычаг — плотность пикселей (dpr): dpr 2 — вчетверо больше пикселей, чем dpr 1. Компонент считает кадры в окне 2 секунды; два окна подряд ниже 45 кадров/с — снижает dpr на 0.25 (не ниже 1). Обратно не повышает, чтобы картинка не «дышала». Кадры длиннее 0.25 с (вкладка в фоне) не считаются. Включается только после прелоадера: во время загрузки кадры идут рывками из-за компиляции шейдеров, и это не признак слабой машины.

## 19. Грабли, на которые мы наступили

1. **Мерцание пола на выходе из комнаты** — две плоскости на одной высоте (пол комнаты и крыша дома). Лечится зазором 0.06 м, `polygonOffset` и `near: 0.25`. Общее правило: **никогда не держите две плоскости на одной высоте**.
2. **Машины ездили сквозь дом** — первая версия просто «заворачивала» машину в начало, не думая про геометрию. Теперь есть перекрёсток и конечный автомат с поворотами.
3. **Деревья закрывали вывески** — раскладка деревьев/скамеек/фонарей не учитывала вывески. Теперь есть проверка `blocked(side, z)`.
4. **Ошибка в GLSL → объекты исчезают без падения.** Один раз в шейдере остался `uv.z` у `vec2` — все здания пропали. Смотрите консоль на `Shader Error`.
5. **Металл = чёрный.** Материал с `metallic ≈ 1` без карты окружения рисуется почти чёрным; машины выглядели «силуэтами», пока не убрали металличность.
6. **`flipY` для экранов.** `CanvasTexture` по умолчанию переворачивает картинку, а UV из glTF уже перевёрнуты — нужно `texture.flipY = false`.
7. **Рывок при повороте к вывеске.** Причина — `atan2(dx, dz)` при `dz → 0` стремится к 90° скачком. Лечится нижней границей `max(dz, 6)`.
8. **Мерцание и «перезагрузка» страницы на телефоне** (в основном резюме, но урок общий): много больших слоёв с `will-change` + высота окна меняется при скролле (адресная строка). Здесь 3D-холст один, `100dvh`, высота не пересчитывается.
9. **Python: `open(f, "w").write(open(f).read())` стирает файл.** При правке файлов скриптами читайте в переменную до открытия на запись.
10. **Текстуры из файлов в некоторых окружениях давали артефакты** → пол и стены рисуются на `canvas`.
11. **Сглаживание, зависящее от FPS.** В «тестовых» окнах с малым FPS камера доезжает медленно из-за ограничения `dt ≤ 0.05`; на реальных устройствах это незаметно.

## 20. Как проверять изменения

1. `npm run dev`, откройте http://localhost:4321.
2. Чтобы быстро перейти к нужному месту сцены, в консоли браузера:
   ```js
   const max = document.documentElement.scrollHeight - innerHeight;
   window.scrollTo({ top: max * 0.3, behavior: "instant" });
   ```
   (`0` — комната, `~0.1` — лестница, `0.2` — выход из подъезда, `~0.9` — набережная, `1` — пирс.)
3. Чтобы узнать прогресс конкретной остановки: `const m = await import('/src/utils/cameraPath.js'); m.stopScroll(3)`.
4. Тест на телефоне: DevTools → режим устройства; обязательно проверьте реальное устройство — на нём важны `dpr`, FPS и размеры карточки.
5. Перед пушем: `npm run build` (и `BASE_URL=/3d-resume/ npm run build` для проверки путей).
6. Модели: `blender -b -P blender/make_assets.py`, затем при необходимости быстрая отрисовка из раздела 13.

Если сцена пустая, проверьте по порядку: консоль (ошибки шейдеров/загрузки), вкладку Network (загрузились ли `models/*.glb`), `asset()` для путей, и подождите — на слабой видеокарте первая компиляция шейдеров занимает секунды.
